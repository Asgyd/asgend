# ASGEND — продолжение реализации (19 октября 2026)

## Реализовано в этой итерации

- Добавлен RPC `workspace_read_chunk`: безопасно открывает файл внутри workspace через существующую проверку относительного пути и `O_NOFOLLOW`, читает не более 64 KiB через `pread`, возвращает размер файла, offset, следующий offset и `eof`. По возможности фрагменты заканчиваются на newline; если строка длиннее размера фрагмента, чтение продолжает работу на допустимой границе UTF-8.
- TUI использует потоковое чтение при открытии файла. Фрагменты подгружаются по мере прокрутки; у начала текущего фрагмента можно вернуться к предыдущему. Просмотр больше не ограничен размером в 1 MiB; редактирование через внешний редактор намеренно по-прежнему ограничено 1 MiB и читает исходный полный файл через `workspace_read`.
- Предпросмотр отображает позицию в большом файле, поддерживает режим без переноса строк и горизонтальный сдвиг колесом мыши. Вертикальное колесо и `PgUp/PgDn` работают с предпросмотром и лентой событий.
- Для drag-selection включено SGR button-motion reporting (`1002`); движение с зажатой левой кнопкой обрабатывается TUI. Горизонтальное колесо в правой панели переключает Files/Goals, а в ленте событий прокрутка основана на визуальных строках, а не только на индексах плиток.
- Добавлены проверки потокового чтения файла больше 1 MiB, последовательности offsets, запрета выхода за workspace, stream metadata библиотеки TUI, а также PTY-проверки горизонтального и вертикального колеса. Обновлены README, архитектурное описание и протокол.

## Оставшиеся границы

- Внешнее редактирование больших файлов не поддерживается: лимит сохранён на 1 MiB, чтобы не записать обратно только открытый фрагмент вместо всего файла.
- Для очень длинной строки, не содержащей newline в пределах фрагмента, просмотр продолжает чтение на границе UTF-8; стык фрагментов не является редактором строк с неограниченной длиной.
- PTY-регрессия покрывает навигацию по каталогам, предпросмотр, колёса мыши, drag-selection, редактирование, изменение размера и восстановление терминала. Для drag-selection тест выполняет press → held-button motion → release → Enter и проверяет, что открывается именно целевой файл.
- Дополнительные элементы общего roadmap ASGEND остаются отдельными задачами, см. `docs/IMPLEMENTATION_PLAN.md`: тонкая отмена сетевых запросов модели, оценка token budget, TLS deployment, усиленная изоляция недоверенного кода, multi-tenant quotas/audit/metrics и распределённая очередь.

## Актуальное продолжение: MCP restart/backoff supervision

- Добавлен отдельный supervisor thread для каждого stdio MCP-сервера. Он проверяет процесс примерно каждые 300 мс и отслеживает завершение child-процесса. Transport-level ошибка записи или закрытый/зависший ответ выставляет запрос на восстановление; корректные JSON-RPC ошибки от самого инструмента не приводят к ненужному перезапуску.
- После отказа процессная группа очищается, private sandbox удаляется, дескрипторы и буферы закрываются. Процесс поднимается повторно без рестарта ASGEND с exponential backoff 1, 2, 4, 8, 16, 30 секунд (потолок 30 секунд); неудачные handshake и `tools/list` проходят очистку и повторяются. Shutdown посылает stop-сигнал supervision-потокам и делает `pthread_join` до уничтожения mutex/освобождения runtime.
- При восстановлении повторяются handshake/discovery и `tools/list`. Уже опубликованные alias/schema сохраняются как неизменяемый snapshot, чтобы избежать гонок с worker-потоками; новый набор MCP tools подхватывается при перезапуске ASGEND. Streamable HTTP endpoint не запускает child-процесс и не проходит через этот supervisor. Ошибка самого первого handshake по-прежнему считается ошибкой старта.
- Добавлен `tests/mock_mcp_restart_server.py`: fixture падает после первого успешного `tools/list`, повторно стартует при supervisor и затем выполняет echo tool. В integration suite добавлена проверка повторного handshake и реального вызова инструмента после восстановления.
- Обновлены README и архитектурный/implementation roadmap.

## Продолжение: очередь задач, dead letters и graceful drain

- Автоматические повторы задач теперь используют сохранённое в SQLite поле `next_attempt_at` с экспоненциальной задержкой 1/2/4/8/16/30 секунд; повторная постановка после аварийного завершения worker-а применяет ту же задержку.
- Добавлены операции JSON API `dead_letters` и `retry_task`. Первая выдаёт список терминально упавших задач с последней ошибкой и попытками; вторая возвращает failed-задачу в очередь на одну дополнительную попытку, не сбрасывая исторический счётчик и события.
- Штатное завершение прекращает выдачу новых задач, отпускает ещё не начатый claim без расходования попытки, оставляет очередь durable в SQLite и ожидает завершения уже выполняющейся работы. `health.draining` отображает состояние drain.
- Добавлена интеграционная проверка миграции/восстановления с backoff, просмотра dead letters, ручного redrive и сохранения `task_redriven` в event history.
