# Native Flutter Cowork voice and workspace snapshots

## Runtime topology

Flutter does not load LFM3 weights or run inference in-process. It records an audio clip and calls the separate ASGEND voice gateway, which forwards multimodal requests to the configured `llama-server` endpoint. The gateway builds a revisioned report; only the explicit `confirm(session_id, revision)` call enqueues a normal task in ASGEND Core.

```text
Flutter Cowork UI
  ├─ microphone -> mono 16 kHz WAV (max 3 minutes / 20 MiB)
  ├─ selected text / project context / workspace image
  └─ HTTPS / loopback HTTP -> voice_gateway (8788)
                                  └─ OpenAI-compatible API -> llama-server (8787)

Voice gateway -> revisioned report -> user confirmation -> Core task queue
```

## Flutter configuration

In local-core mode open **Connection settings** and set:

- Core TCP host/port and Core auth token as usual.
- Voice Gateway URL, normally `http://127.0.0.1:8788` for a desktop running the gateway on the same host.
- `ASGEND_UI_TOKEN` in the separate voice-token field.

The voice token is persisted in platform secure storage and is never included in settings export or normal logs. The endpoint origin is a non-secret setting. On Android, HTTP is rejected; use an HTTPS reverse proxy/VPN endpoint to the gateway. The gateway's default loopback binding is not reachable through the phone's own `127.0.0.1`.

Android requests `RECORD_AUDIO` at runtime. Each recorded clip is WAV, mono, 16 kHz, up to three minutes and 20 MiB. A failed transfer is retained in the app-private temporary directory with explicit Retry and Discard actions. Pending recordings are removed when the Cowork screen is closed. Optional gateway speech replies are played with `audioplayers`; the text report remains authoritative if an audio payload is missing or cannot be played.

## Native preview snapshot

The **Task Workspace** artifact preview toolbar has a camera action. It captures the rendered preview pane (including the current artifact header, source/preview switch and visible document/site/design/code preview) using `RenderRepaintBoundary.toImage`, writes a PNG to app-private cache and opens the native share sheet. Capture limits are enforced before GPU image allocation: maximum pixel ratio 3, maximum dimension 8192, maximum 16 megapixels, and an encoded output size bounded by the caller (12 MiB for the task-preview action).

The Cowork report surface has a separate action that captures its report panel and sends that PNG to the voice gateway as a multimodal attachment. Neither action uses Android MediaProjection: they cannot capture notifications, other apps, or the entire system screen. Agent-side artifact verification continues to use MCP `render_and_inspect`, which renders Office/HTML/UI artifacts in the isolated workspace and returns its PNG to the main vision model.

## Build verification

The project targets Dart >=3.5 and pins the Flutter CI SDK to 3.29.3. `record` is pinned to the compatible 6.2.x line; `audioplayers` is constrained from 6.4.x upward. The checked-in `pubspec.lock` predates these two additions and must be regenerated by `flutter pub get` in CI/developer environment. The Android manifest includes `RECORD_AUDIO` and app cleartext traffic remains disabled.

The Flutter SDK is not installed in the implementation environment. Python contract tests and gateway tests can run locally, but `flutter analyze`, widget tests and the APK build must be run by `.github/workflows/flutter-android.yml` before release. The repository does not include a Linux/Windows/macOS Flutter platform scaffold; desktop microphone setup is documented in `clients/asgend_flutter/README.md` and is not claimed as a verified native build here.
