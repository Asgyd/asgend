# Повторный аудит производительности — итерация 2/3

**Дата:** 27 октября 2026 г.  
**Исходная версия:** `asgend-performance-audit-final-2026-10-27.tar.gz` (SHA-256 исходного архива проверен).  
**Фокус итерации:** корректность инвентаризации компонентов и статистики хвостовой задержки.

## Findings

### F-01 — неполная инвентаризация конфигурационных файлов (P2, исправлено)

Скрипт исходного аудита учитывал исходные файлы `.c/.h/.py/.kt/.dart/.js/...`, но не показывал отдельным набором Android XML, Gradle-файлы, shell scripts, YAML workflow, SQL, properties и JSON fixtures/config. При этом итоговый отчёт заявлял компонентное покрытие всего проекта. Это не влияло на runtime-код, но делало инвентаризацию неполной для CI, платформенной конфигурации и packaging.

**Изменение:** `scripts/audit_performance_inventory.py` повышен до schema v2. Исходный LOC остаётся отделённым от конфигурации/манифестов; теперь отчёт содержит количество файлов/строк конфигурации по расширению и компоненту. В список исходников добавлена поддержка `.java`.

**Свежая инвентаризация stage 2:** 233 source/test файла, 71 013 строк; отдельно 189 конфигурационных/структурированных файлов, 8 838 строк. Эти значения структурные, включают тесты и JSON data/fixtures; они не означают production LOC.

### F-02 — хвостовые процентили при пяти samples были чрезмерно уверенно подписаны (P1 методология, исправлено)

Старый ANN smoke собирает пять измерений exact и пять ANN. При nearest-rank методе p95/p99 становятся порядковыми максимумами маленькой выборки. Показанные значения математически являются эмпирическими order statistics, но недостаточны для устойчивого вывода о хвостовой задержке. Та же проблема была в load-probe на малых количествах запросов.

**Изменение:** добавлен общий модуль `scripts/performance_metrics.py`, используемый benchmark, Control Plane load-probe и синтетическим ANN тестом. Median/min/max доступны при наличии samples; p95 публикуется с 20 samples, p99 — со 100. Для меньших выборок поле равно `null`, рядом выводится `tail_percentile_status`. Добавлены тесты на пороги 5/20/100 samples. Helper добавлен в install rules, чтобы установленный benchmark продолжал импортировать общую реализацию.

### F-03 — синтетический ANN test имел второй независимый расчёт p95 (P1 методология, исправлено)

`tests/test_memory_ann.py` не пользовался summary helper из benchmark; локальная функция маркировала последний из пяти samples как p95. Она переведена на общий `performance_metrics.py`, чтобы отчёт теста и standalone benchmark следовали одним статистическим правилам.

Это исправляет качество измерений, а не оптимизирует hot path. Не запускались live Control Plane/PostgreSQL, внешний embedding/LLM provider, Android/Flutter/Qt профайлеры. Порог 20/100 — минимальный guard от очевидно недостаточной выборки, а не гарантия статистической точности или SLA.
